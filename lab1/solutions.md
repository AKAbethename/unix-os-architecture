В ходе работы были проверены следующие клавиши и команды:

# Лабораторная работа 4. Файлы и файловая система UNIX

## Упражнение 4.1 Изучение структуры файловой системы

Файловая система UNIX имеет иерархическую древовидную структуру, корнем которой является каталог /. Внутри него находятся системные каталоги, предназначенные для хранения программ, конфигурационных файлов, пользовательских данных, устройств и других объектов. 

Ниже приведен пример использования команд **cd**, **ls**, **pwd**.

![](pictures/lab1-5/cd-pwd-ls.png)


| Каталог  | Назначение                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| `/`      | **Корневой каталог** — начало всей иерархии файловой системы.                                                              |
| `/bin`   | Основные исполняемые команды системы, доступные обычным пользователям. Например, `ls`, `cp`, `mv`.                         |
| `/boot`  | Файлы, необходимые для **загрузки системы**: ядро Linux, загрузчик и связанные файлы.                                      |
| `/dev`   | **Устройства**, представленные специальными файлами. Например, `/dev/sda` — диск, `/dev/sr0` — CD/DVD-привод.              |
| `/etc`   | **Конфигурационные файлы** системы и установленных программ.                                                               |
| `/home`  | Домашние каталоги обычных пользователей. Например, `/home/arkady-student`.                                                        |
| `/lib`   | Системные библиотеки, необходимые программам и компонентам системы.                                                        |
| `/media` | Обычно используется для автоматического подключения съёмных носителей: флешек, CD/DVD и т. п.                              |
| `/mnt`   | Каталог, традиционно используемый как **точка временного монтирования** файловых систем. Именно его мы использовали в 4.5. |
| `/opt`   | Дополнительное программное обеспечение, устанавливаемое отдельно от основной системы.                                      |
| `/proc`  | Виртуальная файловая система с информацией о **процессах и состоянии ядра**.                                               |
| `/root`  | Домашний каталог пользователя **root**.                                                                                    |
| `/run`   | Временные данные работающей системы: PID-файлы, сокеты и другая информация текущего сеанса работы.                         |
| `/sbin`  | Системные исполняемые программы, в основном предназначенные для администрирования.                                         |
| `/srv`   | Данные, предоставляемые системой различным сетевым службам.                                                                |
| `/sys`   | Виртуальная файловая система с информацией об устройствах, драйверах и ядре Linux.                                         |
| `/tmp`   | **Временные файлы**, которые создаются программами и пользователями.                                                       |
| `/usr`   | Большая часть пользовательских программ, библиотек, документации и других ресурсов системы.                                |
| `/var`   | Данные, которые **изменяются во время работы системы**: журналы, кэш, очереди и т. д.                                      |

## Упражнение 5.2 Права доступа к объектам файловой системы UNIX

Ключевая структура прав доступа:

```bash
-rwxrwxrwx
```

Права разделены на три группы: **rwx**, **rwx**, **rwx**

r - read

w - write

x - execute

Каждое право имеет числовую запись:

r = 4

w = 2

x = 1

Следовательно,

```
rwx = 4 + 2 + 1 = 7
rw- = 4 + 2 = 6
r-x = 4 + 1 = 5
r-- = 4
-w- = 2
--x = 1
--- = 0
```

Далее был создан файл **newfile** и были присвоены права для владельца, группы и остального: **644**, что равносильно **rw-r--r--**

## Упражнение 8.1 Типы процессов

Системные процессы - это процессы, запущенные пользователем root. Они не привязаны к определенному терминалу, в поле TTY стоит знак ?. Системные процессы работают на уровне ядра, не потребляют виртуальную память.
Примеры: [kthreadd]

Демоны -- это процессы, выполняемые автономно. Они постоянно работаю в фоновом режиме. Демоны запускаются вместе с системой и завершают работу вместе с ней. Не используют терминал. Демоны запускаются пользователем root и могут быть завершены только пользователем root. Примеры: cron

Пользовательские процессы -- процессы, которые запускает сам пользователь. В поле USER указан определенный пользователь. Аналогично, в поле TTY указан определенный терминал, к которому привязан процесс. Примеры: man, mc, ps aux

При помощи команды 

```bash
ps aux
```

можно найти все процессы системы.

ps -- process status - утилита для просмотра процессов

a - all

u - user - показать список процессов всех пользователей.

x -- показать процессы, которые не привязаны к терминалу (системные демоны)

Системные процессы -- это процессы ядра и нициализации. Имеют PID 1 и 2

![alt text](pictures/lab7/ps-aux.png)


Пользовательские процессы - процессы, запущенные текущим пользователем. Они привязаные к терминалу (в колонке TTY указано pts/0 или tty1). Например, bash, ps aux, mc, vim.

## Упражнение 8.3 Задания и сигналы

Была введена команда

```bash
sleep 200
```

несколько раз и несколько раз была прервана, но разными способами.

![alt text](pictures/lab7/sleeps.png)

Ctrl+C посылает процессу сигнал SIGINT (Signal Interrupt). Это способ завершить программу и вернуться в командную оболочку bash.

Ctrl+\ посылает сигнал SIGQUIT (Signal Quit). Похож на SIGINT, но заставляет ядро системы создать core dump - дамп памяти для анализа.

Ctrl+Z посылает сигнал SIGTSTP (Signal Terminal Stop). Этот сигнал не убивает процесс, он временно приостанавливает его выполнение и переводит в фоновый режим. Процесс замирает и ждет дальнейших указаний.

---

После нажатия Ctrl+Z программа приостанавливает выоплнение процесса, чтобы возобновить процесс, нужно ввести **fg** (foreground)

```bash
fg %<номер процесса из квадратных скобок>
```



После этой команды процесс вновь продолжит выполняться.

![alt text](pictures/lab7/fg.png)
